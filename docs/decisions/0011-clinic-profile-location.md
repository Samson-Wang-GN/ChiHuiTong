# ADR-0011 门诊资料与地址坐标确认

- 日期：2026-09-09
- 状态：已接受（数据与原型边界；真实地图接入待实施）
- 关联：REQ-032、TASK-050～052

> 0.26更新：资料直接写入与普通字段免审规则已被[ADR-0012](0012-clinic-profile-change-review.md)替代；本文件地图方案仍有效。

## 背景与选择

渠道及门诊需要维护展示资料，未来客户小程序需要距离排序和地图。仅保存地址不足以支持准确定位，但地址解析结果也不能自动视为门诊入口。采用“完整地址 → 服务商候选 → 人工核对入口 → 确认坐标”，不采用地址字符串直接推算距离，也不把解析失败替换为默认城市坐标。

项目统一采用GCJ-02，显式保存经度、纬度及坐标系，不混存GPS原始坐标。正式接入优先评估腾讯位置服务，与小程序地图场景配套；当前不引入地图SDK或构建依赖，不锁定后端技术栈。腾讯官方示例说明了地址地理编码及WebService密钥配置：[TencentLBS官方示例](https://github.com/TencentLBS/TencentMapDemo_iOS/blob/master/README.md)。这是能力依据，不代表已经开通服务或获得商业授权。

## 数据与安全边界

- 基础资料新增单张展示图片、业务联系人/电话；原预约手机号统一文案为前台预约手机号。图片不混入资质附件，业务联系人不进入面向客户的公开投影。
- 地址及定位分别保存版本；定位包含地址快照、坐标系、来源、返回精度信息（服务商有返回时）、确认人和时间。地址变化使当前点位失效；旧点位只进审计历史。正式异步解析结果必须比对地址版本，旧请求不得覆盖新地址。
- 正式服务端校验机构范围、字段白名单、版本冲突和上传内容；普通资料维护不能修改机构归属、合同、推广产品、财务或平台审核结果。核心名称/主体/经营地址变化重新审核，不通过修改联系人或图片无故重置已通过资质。
- 上传正式实现需内容解码、安全存储及访问策略；原型的512KB PNG/JPG保护不是生产文件安全方案。
- 发送给地图服务的最小数据为门诊地址/检索地点，不发送患者、业务联系人或联系方式。不在前端泄漏服务端密钥；上线前核验密钥限制、配额、费用、授权条款、失败重试与监控。
- 未确认、失效或待重新审核的坐标不用于精确距离/地图。正式推荐还需检查门诊上下线、合同和产品可用性；资料保存本身不会自动上线。

## 原型与后果

复用Arco Drawer、表单、Upload、Image、Descriptions和提示组件，渠道/门诊共享`clinic-info.js`，平台仅查看。保存保持现有同角色演示存储，保留修改前数据；各角色和两个小程序不做假同步。

原型只为三条明确的虚构地址提供本地固定候选，所有坐标带“演示”标识。其他地址明确显示地图未接入；核对复选框只验证交互，不证明现实坐标正确。真实地址解析、地图点选、实际小程序展示及距离排序仍需正式实施。

## 验证与复审

`python -X utf8 prototypes/verify_clinic_info.py`验证双角色表单、图片读取失败保护、坐标确认/范围/地址失效、资料历史及作用域、平台查看和窄屏。接入真实服务时追加多结果、低精度、无结果、超时、乱序回调、坐标转换和真实门诊入口人工验收。


## 0.25.1交互补充（2026-09-09）

渠道新增/编辑和门诊自维护均复用图片上传与地图核对，位置区紧邻地址。原型采用仓库内SVG绘制虚构示意底图，支持地图点击、标记拖动、方向键微调和缩放；坐标只读，不要求业务人员手填。无地图依赖、密钥或外部请求；正式服务商选择和GCJ-02规则不变。此项替代上一版纯数字校正UI，不替代真实地图接入。示意图点位不代表真实地理准确性。

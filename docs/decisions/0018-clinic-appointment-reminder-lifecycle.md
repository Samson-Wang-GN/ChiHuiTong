# ADR-0018 门诊预约提醒的登录联动与紧凑窗口

- 日期：2026-09-09
- 状态：已接受（设计约束，尚未实现）
- 关联：REQ-039、TASK-067～069
- 补充并部分替代[ADR-0017](0017-clinic-document-pip-prototype.md)的默认大窗和单独开启交互；原试用事实及验证保留。

## 背景与备选方案

用户确认前台主动登录时默认开启尽可能小的预约提醒窗，新预约自动变色/更新文字，人工展开、处理、收起；工作台保留开启入口。Document PiP符合跨Tab常驻及自定义Arco内容，但创建和程序缩放需要用户手势。等待异步登录成功后再开窗可能失去手势，不作为可靠路径；收到消息自动重开/放大同样不承诺。普通网页浮层不能实现跨Tab；系统通知外观受操作系统控制；扩展或桌面程序增加安装维护成本，本轮不引入。

## 决定

1. 登录页开启偏好默认勾选、允许取消并在本机记住。实际点击登录时预开小窗，认证中无预约数据，认证成功且取得门诊权限后再显示。登录失败/退出清理窗口，开窗失败不使登录失败。登录和后台维持同一文档生命周期；无法做到时使用明确的手动开启兜底。
2. 保留Document PiP和现有React/Arco模式，不引入新技术栈；同一来源页一个窗口。紧凑参考320×120、展开参考400×520 CSS像素，受浏览器最小尺寸及缩放约束，不强制窗口位置。真实点击展开/收起，不监听消息自动缩放。
3. 小窗数量与原待确认业务同源；新预约与初始存量区分，ID/版本去重；看过、收起、关闭均不确认预约。“去处理”进入原独立任务页定位具体预约并打开表单，不另建核销或预约旁路。
4. 正式服务端必须提供权限内快照/变化及重连校准，及时响应其他终端处理和会话失效；传输协议、刷新时延与可靠性目标另做技术设计。浮窗仅显示非直接身份字段，完整手机号仍在原详情鉴权访问。
5. 本轮只更新文档。TASK-068再实现新原型并验证真实窗口API；TASK-069跟进真实认证/跨端事件及目标电脑验收。原短信与任务页不被替代，不接入系统通知、音效、扩展或桌面客户端。

## 后果、验证与复审

优点是日常登录无需额外点击、闲时少占屏幕，并复用已有业务校验；代价是自动会话恢复、刷新和人工关闭后仍需主动重开，窗口尺寸无法完全控制。设计必须如实展示失败/断线，不保证电脑休眠或浏览器关闭期间实时提醒。

按REQ-039验收登录预开/慢请求/失败/无权限/卸载竞态、默认偏好、窗口复用、紧凑及展开/收起、存量2+新增3及去重、处理后更新、断线及权限切换。正式跨端、Windows常用缩放及多软件叠放单独验收。无代码或数据迁移，本次不部署；后续可关闭提醒增强并保留原短信/工作台，不回滚预约事实。

2026-09-09核验：[MDN requestWindow](https://developer.mozilla.org/en-US/docs/Web/API/DocumentPictureInPicture/requestWindow)要求短暂用户激活；[Chrome官方说明](https://developer.chrome.com/docs/web-platform/document-picture-in-picture#resize_the_pip_window)说明用户手势缩放、浏览器尺寸限制及来源窗口生命周期。实际兼容性以能力检测和目标浏览器验证为准。

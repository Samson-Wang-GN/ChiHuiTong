# ADR-0016 核销锁费、账期切换与未结算撤销

- 日期：2026-09-09；状态：已接受（本地交互原型）
- 关联：REQ-037、REQ-038、TASK-065。覆盖ADR-0005/0009/0014中冲突的旧演示行为。

## 决定

复用原React/Arco组件，不引入后端或依赖。共享rules.js使用十进制字符串和BigInt整数运算四舍五入至分；分配先计算两方金额，平台取剩余分，组合超额拒绝。避免二进制浮点把1.005算成1.00。核销保存费用及规则版本，旧核销不随调价重算；门诊仅展示自身获客费，不展示伙伴分配。

结算周期经渠道提交、平台批准后立即更新合同版本；下一新周期出账日扫描所有历史未出账有效交易，排除已归属账单及撤销交易。不采用修改即即时出账、不重新排列旧单。原型提供显式独立样例，不伪造真实跨角色审批或定时调度。

付款期限按自然日、次日起算；逾期提示与服务上下线状态解耦。当前已暂停的旧缓存不擅自上线，需平台核实历史依据。机构管理员处理整单，业务员只取本人交易投影及小计，禁止写回局部账单，导出同一范围。

未结算撤销在核实未决支付后移除有效明细、改账单版本及金额，保留移出明细和日志；已结清拒绝撤销。空单取消，不伪造到账。特殊补核销撤销从已用转待恢复，恢复系统完成、不建门诊待办；客户基于本次撤销申请后一次释放。不新增退款/负向调整业务，采购订单原退款不变。

## 取舍和边界

没有采用整单删除、退款后补差、批量人员交接或复杂余额账户。前端原型保存before-0.29备份，不删除旧流水；正式不可变账单版本、服务端支付验签/查单/事务幂等和权限查询必须另行实现。默认打开Web为已登录评审视图；退出后可演示预开通手机号与验证码流程，不是生产认证。手机号、验证码、地图、二维码和支付全为虚构演示。

机构负责人和稳定业务ID保持解耦；业务员交接继续延期，不建设交接功能。各角色数据独立，不能把测试夹具的同号预约当成跨端业务同步。

## 验证

verify_rules29.py覆盖舍入/守恒、自然日、跨期归集/重复拦截、手机号登录、本人明细导出、有效预约晚核销、核销锁费、未结算修订、已结清/未决拦截及特殊恢复。相关原回归更新旧断言，具体执行结果及边界见TASK-065。后端上线前须补真实鉴权、并发/迁移、支付回调及微信真机验证。

# ADR-0017 门诊真实画中画悬浮工作台试用

- 日期：2026-09-09；状态：接受（仅原型试用）
- 关联：REQ-039、TASK-066；不批准正式提醒架构或后台推送接入。

> 0.29.2后续决定：[ADR-0018](0018-clinic-appointment-reminder-lifecycle.md)部分替代默认大窗和独立点击开启的交互设计，确认登录点击预开紧凑窗及人工展开/收起。此处保留0.29.1历史试用和测试事实，不表示新交互已实现。

## 背景与选择

用户希望先体验能跨Tab常驻的醒目提醒。采用浏览器Document Picture-in-Picture，而不是普通网页浮层、window.open、桌面客户端或浏览器扩展。只有用户点击才请求窗口；窗口尺寸/位置受浏览器管理，不承诺任意位置或所有系统情景置顶。

沿用React Portal与本地固定Arco组件样式，没有新增依赖。只读视图与主页面共用同一预约状态，点击返回原预约详情进行原有权限和业务校验；不让关闭提醒充当确认预约。模拟数据明确标识，浮窗不显示患者姓名、电话及财务信息；不用“连接正常”描述没有服务端的原型。

## 生命周期与限制

检测安全上下文、顶层窗口和API；拒绝/不支持提示错误，允许用户重试，绝不声称普通浮层能越过Tab。打开请求防重，重复查看复用已有窗。窗口关闭清理视图，组件卸载/pagehide清理定时器并关闭窗口，请求返回时若来源已经退出立即关闭。刷新后需重新主动开启。

5秒延时仅为切Tab演示，不保证后台计时精度；没有真实推送、声音、通知权限、服务端连接或跨设备同步。安装依赖、通知策略和正式推送方案后续评审。

## 证据与复审

2026-09-09核对[Chrome官方文档](https://developer.chrome.com/docs/web-platform/document-picture-in-picture)：用户手势、独立置顶窗口、不超出来源窗口生命周期、位置不可由网站指定、pagehide清理、复制样式等。原型专项通过真实浏览器API测试成功路径，模拟缺能力/拒绝仅测试失败路径；无头自动化不等于Windows桌面叠放已验收。上线前在前台目标浏览器/多应用/锁屏/休眠/断网场景重验，并补真实鉴权与事件传输。

## 当前风险

- 不同上传批次暂不区分追加与重复，资源方误传重复文件会形成新的待领取权益；需通过批次确认和未领取整批回滚控制风险。
- 任一权益领取后整批不可回滚，错误批次一旦部分领取将需要后续异常处置方案。
- 客户档案是平台级共享身份，而资源关系和权益按来源隔离；若查询权限误以客户档案为边界，可能造成跨资源方数据泄露。
- 客户手机号当前不可修改或换绑；如真实换号，只能等待后续需求扩展。
- 门诊直接撤销错误核销、预约超时取消、权益恢复和结算调整形成跨模块事务，需要重点验证权限、幂等与一致性。
- 客户改期需门诊确认，门诊改期需确认已协商一致；改期请求、履约反馈和预约主状态并行存在，需要重点验证原预约时间有效性、并发确认和通知一致性。
- REQ-030保留过期预约权益占用，客户不反馈可能长期占用；系统完成不产生核销/费用。冲突和待确认改期阻止自动处理，过期补核销政策仍待确认。
- 取消授信后不再按金额封顶，门诊应收可能累积；是否保留逾期暂停新预约待确认，不隐含恢复金额风险阈值。
- 线上线下收款、核销撤销及账单金额变更可能并发；需要统一收款协调和版本校验，不得只靠页面按钮禁止重复付款。
- 核销计费、到账冲销和错误核销调整形成跨模块资金类账务链，需要重点验证原子性、幂等和账实一致。
- 新增微信扫码收款属于真实外部资金边界；商户资质/主体、通知验签、查单、重复款、手续费和退款政策未完成联调前不得生产启用。
- 多类合同共同控制资源方、渠道公司和门诊权限，合同生效、到期、终止和版本变更必须统一校验；任何入口漏检都可能产生越权的新业务数据。
- 不记名卡不设激活截止日期，激活前具有长期持有人风险；必须防止可枚举卡号、重复激活、二维码泄露和未授权状态查询。MVP 采用未激活作废、已激活不转让、争议由平台冻结并人工裁决的最小规则。
- Excel 权益从领取日起算有效期且未领取前不开始倒计时，会形成长期待领取数据；后续需要结合实际投放效果评估停止批次剩余权益和数据保留策略。
- 资源方可以查看本方 Excel 或不记名卡关系客户的平台允许全部字段；精确字段清单尚待 TASK-008 确定，在此之前不得把“全部字段”解释为跨来源查询权。
- 开卡订单收款、实体卡制作寄送、取消和退款均包含线下环节，系统状态依赖人工确认；必须通过分权、二次确认、凭证和审计降低错记风险。
- 预约履约冲突当前只记录事实并停止自动处置，尚无标准裁决机制和处理时限；试点运营必须监控未关闭异常，避免权益被长期占用。
- 详细角色权限矩阵、平台异常处理权限和发票能力均已明确延期，不得在 MVP 中通过临时超级权限或非审计操作隐式实现。
- 经营指标和分析报表已明确延后，基础版本不得顺带扩展数据看板范围。

## 已明确限制

- 数据库没有按租户部署或使用数据库RLS；租户隔离由每个业务服务与查询集执行。拥有服务器和解密密钥的管理员是高信任主体；字段加密不防已控制应用服务器的攻击者。
- 短信登录不具备额外MFA；用户选择的手机号+验证码登录已实现，限速不代替运营商SIM安全。手机号真实变更本期不处理。
- 资金操作使用可信网关观察与线下凭证复核；上传凭证不等于收到钱。重复/超额真实款保留异常核对，复杂退款、发票和争议裁决按需求延期。
- 图片/PDF/XLSX结构检查不等于恶意软件扫描；上线前可评估独立杀毒隔离，不能假称本期已经具备。
- 日志不记录敏感原文，因此仅靠异常类型不足以复原任意代码堆栈；运维通过请求ID、脱敏业务状态和对应提交定位。不要临时开启原始报文/请求体日志。
- 上传附件与业务提交失败可能留下未引用文件；当前保留供审计，未自动清理。按引用、保留期和恢复要求设计清理后才执行。
- 覆盖率、已知漏洞扫描和合成并发回归不构成渗透测试、真实支付验收或生产可用性承诺；1万张容量样本不代表无限负载。

## 上线门槛

1. 用户验收真实业务闭环；非作者审核认证/权限、医疗资料、支付及迁移变更。
2. 独立生产密钥/数据库最小权限、TLS/域名、私有存储与备份恢复责任落实；禁止使用测试密钥、合成凭据或测试短信后端。
3. 微信主体/商户/AppID绑定、公钥轮换与回调、短信报备及实际送达、地图授权、两个小程序真机手机号授权完成真实联调。
4. 日历、合同、负责人、联系人、付款期限及通知配置核对；出账漏调度、异常支付、失败任务有运营处理人。
5. 发布前复扫依赖并执行服务器全量回归；版本、证据、回退和数据兼容性明确。不得自动启用公网或生产服务。

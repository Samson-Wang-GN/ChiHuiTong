# 待签合同生成与双方合同交付记录

日期：2026-09-16。REQ-051 / TASK-110 / ADR-0033。本轮为正式Web及后端；小程序正式工程不改，历史原型仅清理口径。

## 操作路径

1. 平台：合同管理→合同模板配置→发布新模板版本。分别选择单店现付或连锁后付，填写平台法定名称、信用代码和已认可的完整正文，确认后发布；没有内置可签法律范本。
2. 渠道：门诊管理→单店入驻申请→填写资料/合同项→保存待签草稿。可以中途离开，在门诊管理或合同管理的“待签合同草稿”继续。
3. 草稿详情：生成待签合同→下载打印→门诊签署→上传完整照片/扫描件→提交审核。未生成或未上传当前版签署件会阻断；正文变更必须重新生成签署。
4. 平台：合同详情同时预览生成PDF、全部签署照片、门诊资料及资质；登记原件收件及平台签署，最终联合审核后才上线。沿用2工作日时限。
5. 连锁：合同管理新建总部合同，允许先不录门店；总部合同通过不自动授权任何门店，门店仍须有效签署覆盖和资质审核。已有主体续签复用主体；单店独立续签不重复开户。

## 边界与决定

- 产品不设置旧三方/历史三方合同类别，渠道不成为门诊签约方；分账、已存附件、费用与账单不删除。旧直接创建合同API不能绕过生成/签署流程。
- 编号稳定、版本递增；模板发布新版本不改写已有打印件。PDF固定带合同字段及费用摘要，随后为认可正文。ReportLab嵌入中文字体，服务端生成和私有加密下载，正文不执行HTML/模板表达式。
- 草稿未提交不创建主体或账号；重复生成/重复提交不重复建档。附件按平台、机构管理员、草稿负责人及合同完整管理范围授权，不能因一间连锁店权限下载整份合同。
- 门诊退回补正复用原门店和主体，新提交对应新的打印版本及签署件；不删除旧版本或审计。
- PDF技能用于服务器生成和逐页视觉检查。正式模板尚未提供，合成模板显著标注禁止实际签署；只进入临时库，不写持久验收库。

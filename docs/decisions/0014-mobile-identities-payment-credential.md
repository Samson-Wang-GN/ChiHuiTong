# ADR-0014 移动身份、付款与预约固定凭证

- 日期：2026-09-09；状态：已接受（仅原型）
- 关联：REQ-036、TASK-060～062；补充ADR-0004、0005、0013。

## 决定与取舍

沿用独立React/Arco移动原型，不增加技术栈。门诊以管理员/员工区分最小职责；员工保留预约核销履约，合同和账单必须管理员。入口隐藏、路由和财务转换函数均检查身份；不扩展成细粒度权限配置。旧移动缓存没有身份依据时重新登录，不自动升级；门诊Web旧角色只做明确标签兼容，资源方/渠道仍为业务员。

门诊独立加载`finance.js`，提供管理员合同摘要、账单详情、可读图片凭证上传和同机微信支付演示。凭证提交与平台审核分离，不给门诊审核按钮；模拟结果在显式评审控件内返回，失败/取消/未知不结清，待审/在线未决互斥，重复和版本冲突拒绝。账单固定为历史样例，支付成功只结清该账单关联的R1及540元历史底账，今日新增核销不被一并结清；R1已撤销且未结清时阻断旧账单支付，等待正式账单修订能力。

未采用同机显示支付二维码再扫码的路径，避免手机无法扫描自身屏幕；此处是业务交互约定，不是已经核验和接入微信支付API。真实商户、服务端验签查单/关单、账单修订、并发和异常退款独立实施。

客户权益卡使用产品规则快照并直达带权益编号的适用门诊查询；原型无规则快照的旧样例使用明确的一次1份演示通用规则，正式历史数据不得猜测补规则。预约详情前部直接渲染关联权益的固定视觉凭证，不为展示创建/消耗权益。未来已确认预约可先展示，但实际预约时间未到不能扫码核销；取消、核销、恢复、冻结等阻断状态不显示可用码，系统完成仍保留原补核销约束。

## 边界、恢复与验证

仅独立浏览器演示，不是真实登录、安全鉴权、支付或跨端审核。图片限PNG/JPG、单张512KB、最多3张是本地存储限制，不是正式上传容量政策；解码校验不是安全扫描。原始移动数据保留`before-0.28`备份，不自动删除或同步他端数据；前端存储可读，不能用于真实财务或患者数据。

`verify_mobile_access.py`验证身份深链接/提交边界、付款异常、附件、旧角色标签、固定码状态和窄屏；`verify_mini.py`及`verify_overdue.py`保留原领取/预约/核销/恢复闭环。服务端鉴权、事务以及微信开发者工具/真机验收为正式上线前置条件。

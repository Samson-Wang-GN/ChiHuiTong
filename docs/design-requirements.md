# 齿慧通前端设计要求：Arco Design

- 状态：项目强制设计基线，原型和正式 Web 开发共同遵循
- 版本：1.19，2026-09-12（0.32业务交互要求，Arco基线未变）
- 关联：REQ-019、TASK-019、TASK-020、ADR-0001
- 适用：平台、客户资源方、门诊渠道公司、口腔门诊四组 Web 后台；小程序遵循[移动设计适配要求](mini-program-design.md)，不直接套用桌面组件尺寸。

## 1. 规范依据与适用优先级

0.32当前交互要求：合同详情区分新合同适用/最近历史版存量适用，核销详情展示实际锁定版本和渠道（费率仍按权限）；合作方结算列表新增“无需付款”状态Tab，0元详情保留明细/Excel和操作记录、无对账/付款/收款确认按钮；管理员工作台每天提醒本方待办，不把已读当确认；门诊业务联系人及电话必填，草稿可缺、提交审核/上线必须补齐。

Excel映射和单客表单增加性别/年龄/职业三个可选字段，缺列可跳过；说明只补齐空缺，不覆盖已有资料，客户编号不参与关联。微信支付仍本期开发，原型演示明确模拟；真实配置不齐显示不可用原因及线下凭证替代路径，不伪造可支付码或实际到账。本节同步执行及视觉验证见TASK-078/079，当前旧原型尚未实现0.32。

本文件是基于官方材料整理的项目执行规范及官方完整规范索引，不是官方网站逐字镜像。标记“官方”的条目来自官方设计文档或组件源码；标记“项目约定”的条目是为齿慧通确定的实施要求。没有标记的业务交互要求均为项目约定，不应冒称 Arco 官方要求。

优先级为：已确认业务和权限规则 → 本项目设计要求 → 固定版本 Arco 组件实现 → 官方设计原则及各组件设计规范。发生差异必须记录原因，不能通过任意 CSS 覆盖规避评审。官方旧设计文档与当前组件存在差异时，明确选择并登记，不混用版本。

核验来源：Arco 官方站点、官方 GitHub 仓库。源码参考快照 `c2b050d9c7ce94bebba94f616a0721344231caac`；原型组件包固定为 `@arco-design/web-react@2.66.16`，React/ReactDOM `18.3.1`。这组依赖用于可运行原型，未决定后端技术栈。正式 Web 开发继续使用 Arco 官方组件体系，版本升级另行验证。

## 2. 设计原则（官方概念，项目落地）

官方价值观为清晰、一致、韵律、开放。设计应及时反馈、贴近现实、保持一致、防止错误、降低记忆负担、突出重点，并提供可恢复的错误帮助。

项目落地要求：工作台直接呈现待处理事项及入口；相同业务在各角色后台采用一致命名和状态颜色；业务状态与动作相邻；明确显示操作主体和影响范围；保留用户输入直到提交成功；失败提示说明原因及下一步。主界面使用客户、权益、预约、账单等业务用语，不显示数据库字段或接口错误码。

## 3. 色彩与状态

官方默认主色 `#165DFF`，用于主要操作、当前菜单和链接；成功 `#00B42A`、警告 `#FF7D00`、错误 `#F53F3F` 来自默认色板。中性色承担文本、边框及背景层次。项目使用官方主题 CSS 变量：`rgb(var(--primary-6))`、`--color-text-1/2/3/4`、`--color-bg-2`、`--color-fill-2`、`--color-border-1/2`，禁止逐页自创主色。

| 项目语义 | 色彩/组件 | 用例 |
| --- | --- | --- |
| 主要动作、当前选择 | 主色 / primary Button | 提交申请、当前菜单 |
| 正常、完成 | success Tag / Alert | 已生效、已结清 |
| 等待或临近期限 | warning Tag / Alert | 待审核、即将到期 |
| 失败或业务阻断 | danger Tag / Alert | 逾期、冻结、数据异常 |
| 信息或历史状态 | 中性或信息 Tag | 已取消、已下线、已记录 |

状态必须同时有文字；颜色不能作为唯一判断依据。逾期提醒需说明欠款、截止时间和恢复条件；“已提交付款凭证”不得用成功色暗示“已结清”。遮罩及组件交互色由 Arco 原生样式提供。

## 4. 字体、数值与排版

官方样式指南建议最小文字12px、正文14px、少量字号层级，主要字重400/500，重点数字可600。官方旧文档提到 Nunito 和1.4倍行高，当前源码 `default.less` 使用 Inter 优先的系统回退字体和 `1.5715` 基础行高。本项目以固定包的实现为准，不额外下载字体，避免不同页面混用两套规则。

项目正文14px；辅助说明12px；区域标题16px；页面标题24px；工作台待办数字28px为项目约定。字体回退覆盖 PingFang SC、Microsoft YaHei。文字自然换行，不缩小到12px以下。金额右对齐并显示单位；正式金额固定两位小数和千位分隔，未知金额用“待定价”，不能显示零冒充未知。

日期统一 `YYYY-MM-DD`，时间采用24小时制 `HH:mm`，精确事件用 `YYYY-MM-DD HH:mm:ss`；项目时区 Asia/Shanghai。数量使用阿拉伯数字并说明份、张、条或元。只在业务明确允许时使用省略号，详情可获得完整文本。

## 5. 间距、尺寸、圆角、阴影

官方全局尺寸以4px递增，控件高度 mini/small/default/large 为24/28/32/36px。官方间距变量包含2、4、6、8、10、12、16、20、24、32等值，不能简单宣称所有间距均为8倍数。官方圆角 small/medium/large 为2/4/8px，另有圆形。

项目控件默认32px，表内紧凑按钮允许28px；页面间距24px，卡片内边距20px，区块间距20或24px，关联控件间距8或12px。基础卡片4px圆角；不添加夸张圆角或全局阴影。浮层阴影、边框和遮罩使用 Arco 默认组件。

## 6. 后台布局与角色隔离

官方 Layout 支持顶部、侧栏、内容区及组合布局。项目采用顶部64px、左侧224px、内容区自适应的后台布局。这些具体尺寸属于项目约定，不是官方固定要求。

每个角色独立目录、HTML入口、菜单、样例数据及存储命名空间。页面内不设置跨角色切换器，不把四组原型拼成一个页面。允许共享官方组件、字体规则和公共布局代码，不共享角色业务列表。保险、银行、经纪代理共用“客户资源方”业务能力组，机构类型保留固定枚举。

页面结构：面包屑 → 标题及一句说明 → 主操作 → 必要的状态提醒 → 筛选与业务表格 → 分页。工作台使用真实待办数量与任务入口；仅平台/资源方独立概览按REQ-029增加客户权益趋势，不增加营销大屏或新客指标。

桌面重点校验1440×900及1280×800；宽度不足时表格内部横向滚动，操作列固定。辅助窄屏检查保证主要操作可访问；小程序的375/390/430px适配及触控约定见独立移动设计文档。

## 8. 表格和筛选

所有后台列表必须使用状态 Tab（REQ-021），替代状态下拉框。使用官方 `Tabs` 的 `line` 类型、默认字号及下划线，页签位于白色列表面板顶部，查询工具栏和表格属于当前 Tab 内容。默认“全部”；标题为“状态（数量）”，计数包含当前权限/合同范围与关键词匹配的全部记录。零数量状态保留，不能依据搜索结果增减页签；状态变更更新计数但不自动跳转。切换Tab或关键词回到第一页，保留其他范围；导出遵循当前Tab。单状态业务也使用统一结构。

采用 `overflow="scroll"` 处理长状态名及多页签；不截断或强行缩小到12px以下。官方建议标签简短、一次展示不超过7个，项目因完整业务状态需要可超过7个，以滚动保留完整含义，不合并状态。依据：[官方Tabs设计规范](https://github.com/arco-design/arco-design/blob/main/site/docs_spec/components/tabs.zh-CN.md)、[官方Tabs接口](https://github.com/arco-design/arco-design/blob/main/components/Tabs/interface.ts)，2026-09-07核验；固定本地2.66.16包通过浏览器验证。状态数量不属于新增经营指标。

列表至少包含主体名称/编号、业务状态、关键时间和操作。把跨记录对比需要的字段放在表格，把较长说明、凭证、完整联系方式放详情。查询和状态筛选可组合，清除后恢复结果；过滤后分页回到第一页；无结果提供调整筛选入口。所有导出明确当前范围和字段，不导出另一角色数据。数字型列使用数值排序，日期型列按时间排序，不能把金额作为字符串排序。

原型默认每页8条，可切换每页条数；正式页大小按业务密度确定。列表需覆盖长名称、大金额、空字段、无结果和网络失败。客户资源方仅在自身关系内查看完整客户字段；渠道及一般门诊列表手机号脱敏；门诊预约详情按业务权限提供完整联系号码。

## 9. 表单、上传与弹窗

REQ-046覆盖旧Excel分开确认交互：上传自动读取/匹配，上方Arco Table直接展示原始列头及前10行，下方必需字段对照使用Select、明确文字与错误色；可选字段/工作表与表头设置用Arco Collapse收起。销售底部仅“下一步”，自动校验/确认后推进；错误持续显示并定位对应字段，不以toast替代。原文件预览是无业务状态的数据样本，不强加状态Tab；全量校验结果继续按有效/异常Tab。

短表单采用Modal，官方建议宽度400/520/720px，项目常用520px；长合同、门诊入驻等使用右侧720px Drawer。浮层宽度不得超屏，正文可纵向滚动，标题与底部动作固定。输入型浮层禁止点击遮罩丢失填写内容；取消时如有修改，提供离开确认或保留草稿。

先校验再提交，提交中禁用重复按钮；错误不清空输入。门诊三方合同无授信字段；结算周期只能周结/月结，展示对应付款期限。渠道从门诊详情首签/续签并提交平台审核，三方主体绑定当前门诊；旧有效版本不被待审表单覆盖。资源方下单填写采购价（默认0元）、来源名仅选本方列表；非零先全额确认到账，平台再审核开卡及有效期，不静默改价。

0.18原型已增加无敏感信息的本地图片放大/逐张查看、PDF预览及下载，PNG/JPG/PDF单份512KB、最多10份为本地演示存储限制。图像可解码和PDF文件头检查不等于正式安全扫描；正式版仍需完整实现上传、安全校验、访问权限、版本冻结与审计。门诊入驻、资质变更、首签、续签审核页均展示本次全部照片及附件，标记数量、名称、类别和版本；失败可重试，必需文件不可读则不能审核通过。

## 10. 业务交互边界

0.20强制补充（REQ-025～027）：

- 合作方结算主状态：待对账确认/待付款/待确认收款/已完成；平台付款后仍用等待色，不显示已完成。收款方同单详情核对凭证及流水，填实际到账日并主动勾选到账确认，平台无此按钮。异常反馈/核查不重新开放付款入口。
- 月度归集页内显示历史原核销日期、门诊结清日期、收款机构及已入单标识；未回款/部分到账/凭证待审不能归集，已入单不重复。每笔预约显示门诊结算状态，详情显示门诊账单及结清日期；与合作方付款/收款进度分开。

- 平台、资源方、渠道、门诊各自独立任务页。工作台每个待办入口带任务类型进入具体任务列表，详情内直接使用原业务操作；状态Tab与已处理历史同源，不靠“标为已处理”绕开业务结果。
- 推广产品主档同时展示内部名称与外部产品名称，后台内部名称为主，两个小程序显示外部名称；来源品牌另列。产品编号不随改名变化，历史交易固定名称快照。
- 对账单详情展示逐笔交易，交易编号、时间、门诊、推广产品、数量、费用、分配快照、本方金额和状态；金额右对齐，超宽表内部滚动，交易编号固定以便定位。状态Tab、搜索与下载Excel使用同一范围，导出覆盖全部匹配分页，文件明确整单/筛选合计。
- 合作方“确认对账单”后为待付款，不使用已付款的颜色或文案；平台“登记付款”显示收款方、已确认版本、全额金额、日期、交易参考号和全部可读凭证，二次确认实际已线下付款。平台不能代合作方确认，合作方不能登记付款。
- 原型实际付款仍未接入；旧汇总缺明细显示补充提示，不伪造交易。出账/明细导出是业务处理，不扩展经营分析报表。

合同与方案页面整合遵循REQ-022/024：资源方“合作合同与推广产品”、渠道“平台合作与推广产品”各一个只读页，上方合同摘要、期限及附件，下方授权方案状态列表，历史版本可展开。资源方一份主合同、渠道同一时点一份有效合同，均支持多方案；配置只在平台。渠道门诊相关合同和优惠不保留孤立一级列表，而进入“门诊管理 → 具体门诊 → 合同与续签 / 推广产品”；三方签约人明确为平台、渠道、门诊，渠道提交、平台审核。

平台机构管理详情的“合作合同”提供“推广产品配置”入口，带入并明确显示本机构合同筛选范围；推广产品配置表显示方案、获客费、分配模式、带单位数值、本方元/次、授权有效性及启停状态。新增/编辑使用 Arco Form、Select、InputNumber 和 Drawer，显示实时分配试算；修改已有条款不能替换合同或方案，应新建条款。分配超额、重复授权等错误保留输入。合作方仅可查看自身条款，门诊不显示他方费率。来源展示名维护提供机构快捷入口，编辑不允许偷偷改变来源机构。

## 11. 动效、可访问性与反馈

官方默认动效变量为0.1至0.5秒，标准曲线见默认主题源码。项目采用组件默认动效，支持系统减少动效偏好。不得用持续动画分散后台任务注意力。

全界面可键盘遍历、焦点可见；按钮有可理解名称；图标操作有标签；表单标签关联输入；浮层继承焦点管理并在关闭后恢复到触发位置。关键文字对比度以可读为目标，不能仅以采用组件为理由免除人工检查。错态同时说明字段、原因、改正方式；异步失败提供重试。

## 12. 原型与开发验收

1. 四组入口与数据独立，任一组不加载其他组业务配置。
2. 页面使用本地固定版本的真实Arco组件，基础组件无手工仿制皮肤。
3. 字体、颜色、间距、控件高度和弹层遵循本规范；项目偏离项登记原因。
4. 导航、查询、筛选、详情、表单校验、状态变化及导出可交互；刷新后的演示修改仍可查看，可重置。
5. 关键角色禁用能力无操作入口；来源归属、三方合同与账单文案正确，无授信配置/显示。
6. 加载中、空结果、失败重试及业务阻断状态均有明确设计。
7. 桌面尺寸不遮挡主操作，表格滚动不导致全页面不可读；浏览器无脚本错误。
8. 使用人工构造的数据，附件及导出明确演示用途。
9. 正式上线前补齐后端权限、事务、真实短信、收款校验和自动任务；原型通过不等同于业务实现通过。

变更本规范时更新版本、来源日期、影响页面和验证证据；组件升级需重验弹层、表单、表格、焦点与关键业务流程。禁止在开发时另起一套设计风格。

## 0.22客户权益概览（项目约定）

- 平台与资源方各自独立“客户与权益概览”，平台可选资源方，资源方无跨机构选择；不是工作台待办，也不新增操作客户权益的按钮。
- 页面为范围筛选、数量指标、三项转化率、按产品状态Tab的汇总表。单位人/张/次/份明确，主要数值28px，原生Arco Card/Button显示可点击指标；所有产品行的指标同样可点击。字段保留内部产品名称。
- 点击指标使用右侧Drawer；保留来源范围，顶部解释口径，日/周/月Select及累计/净变化切换，下方曲线、精确数据与状态明细。比例支持分子/分母明细，分母0显示“—”且曲线留空断点。
- 曲线采用原生SVG，不仿造Arco控件；遵循Arco主色、文字及边框变量，零基线、时间轴、点值和单位可见，提供等价表格和Excel。无图表库新依赖，依据ADR-0008。周/月按期末集合重算，不能图形平滑掩盖数据或取消下降。
- 日期范围明确叫“开卡批次起/止日”，观察截止日期另外常驻显示；禁止把批次选择期与统计事件时间混为一谈。数据覆盖不足持续提示，不能用0冒充未知。
- 抽屉宽度不超过视口，图形随正文宽度缩放，表格内部横向滚动；窄屏仍能切粒度、关闭并返回原筛选。键盘按钮可到达明细，曲线不是唯一访问渠道。加载、失败重试、空范围和零分母有独立反馈。


## 0.23过期预约交互（项目约定）

- 统一名称“过期预约待办”，取消2小时提醒；任务列表按待处理/待补核销/异常搁置/已关闭分Tab，原待办关闭保留原因及历史。后续客户报已到诊是新任务，不能把原任务历史擦掉。
- 预约四主状态不变；系统超时完成同时常驻显示警告说明“尚未核销”，门诊取消未到同时显示“权益仍占用”。不得单独以成功色暗示治疗已完成或产生账单。
- 客户首页待处理提示与是否读过消息分开；明确门诊、时间、产品外部名称、占用数量及处理入口。两个反馈按钮分别二次确认，不混入普通预约取消。
- 门诊待办详情直接处理患者未到及协商改期；补核销复用门诊小程序扫码核对、原数量/获客费和服务完成勾选，不另建自由补费表单。期限/冲突/已恢复等阻断原因常驻。
- 后台使用现有Arco Table/状态Tabs/Drawer/Descriptions/Modal，抽屉宽度不超视口；小程序用移动卡片、长按钮、滚动状态Tab。原型时钟及跨端不联动须明确为评审限制。


## 0.24机构内合同与推广产品配置（项目约定）

平台使用与门诊一致的“列表单一详情入口 → 右侧详情抽屉”路径。详情使用Arco线型Tabs的“机构资料 / 合作合同 / 推广产品配置”，顶部持续展示机构名称、编号、类型；不增加独立合同一级菜单。全局推广产品与门诊三方合同维持原入口。

合同与配置区用白色内容面板、状态Tab、关键词和分页；宽表水平滚动并固定操作列。分配值明确标注%或元/次；添加、编辑使用现有Arco Form/Drawer和实时试算，不更换组件体系。新合同的主体与类型禁用选择，新增配置合同下拉仅含当前机构合同；无合同给出提示并禁用添加。

返回机构列表保留关键词及状态；切换机构清除上一机构合同筛选。工作台任务在独立任务页打开机构业务抽屉并原地审核。旧有范围链接只在可验证匹配时显示详情，无范围返回机构选择，参数不匹配提示而不展示其他机构合同。本节是项目交互约定，不冒称Arco官方业务规则。


0.24.1交互对齐：机构与门诊详情均为1000px右侧Drawer（不超视口）、标题“名称 · 管理模块”、顶部上下文Alert、内部线型业务Tabs。列表不并列机构资料/合同/配置链接，不用整页切换或返回列表按钮。关闭抽屉保留列表状态、关键词和页码；普通详情重开默认资料分区，待办和旧深链接可定向分区。机构新增/合同登记/产品配置长表单为760px次级Drawer，取消未保存内容需确认；短审核原因保留Modal，保存后回到同机构同分区。不得为了表面一致增加门诊专属业务到机构管理。


## 门诊资料维护与定位（REQ-032）

渠道从门诊详情进入“维护门诊资料”，门诊从“门诊资料”进入同一Arco表单抽屉。保持760px上限、窄屏单列和固定底部保存；定位紧邻经营地址，之后为联系信息和展示图片分区，不用另一套视觉组件。前台预约手机号与业务联系人电话分别命名；业务联系人不得出现在客户展示预览。

单张展示图片使用Upload和Image，支持替换、移除、预览；无图显示Empty，读取失败保留旧图，读取中禁止保存。地址改变立即撤销原坐标，解析失败显示可理解错误。地图及入口标记是主要核对界面，候选地址和确认状态常驻，自动回填的经纬度及坐标系仅作辅助只读信息；核对确认不可由解析成功自动代替。所有原型坐标和按钮明确标记“演示”，真实地图尚未接入。

客户小程序展示预览只用于核对当前草稿，不代表已发布或跨端同步。已审核门诊所有资料修改均提交平台审核；待审核或退回不覆盖生效资料。以上均为项目交互约定。


0.25.1：渠道录入和编辑门诊均使用完整图片上传与地图核对组件；允许上传、替换、删除展示图。地图原型用本地SVG道路/地标示意（无新依赖），提供点选、拖动标记、键盘方向微调、缩放、恢复候选与确认，配套Arco按钮、Checkbox、Alert；图内及图外常驻“虚构示意、非真实位置”提示。地址改变移除旧地图候选，移动点位撤销确认；缩放仅改变视图、不改坐标。正式版本必须替换为真实服务商地图，不能把此图当成真实定位能力。


## 0.26资料变更审核（REQ-033）

门诊/渠道不提供待确认时限输入，仅展示小时数及“仅平台可修改”。新增门诊沿用默认24小时。已审核资料编辑主按钮为“提交变更审核”，草稿门诊仍为“保存门诊资料”；没有变更提示无需提交，待审核禁用再次修改。退回后重新编辑带回申请内容，并以新申请编号提交，不抹去旧拒绝记录。

当前生效资料与“资料变更审核”分区同时可见，变更列表使用待审核/审核通过/审核不通过状态Tab。详情用960px上限Arco Drawer，字段对照表标记修改项，同时展示两版图片、全部资质附件、提交人和审核原因。平台从独立待处理任务页打开相同门诊详情，不另造自由修改主档的审核入口。通过一次性发布申请版本，退回保留原资料；审核意见必填，冲突和重复处理明确报错。


## 0.27机构账号与业务日志

资源方/渠道保留独立后台入口，机构内身份区分管理员/业务员；顶部“本机构演示账号”用于评审范围切换，明确不是实际认证。账号管理使用Arco状态Tab和短表单Modal，身份用Select；平台创建的初始管理员身份锁定并说明原因。平台新增机构长表单同时填写初始管理员姓名/登录手机号，成功同单登记，不额外出现功能权限勾选矩阵。

门诊列表独立“上线/下线”按钮，弹窗显示对象、影响与必填原因；删除详情资料区旧暂停/恢复动作。详情保留原业务Tab并新增“操作记录”。门诊账单、合作方结算单和采购订单详情统一“操作记录”名称，展示当前对象的新事件与历史记录；时间、操作人、身份、动作、原因及前后状态清晰，宽表内部滚动。日志只读，旧缺失字段明确显示未记录，不能用虚构精确时间装饰历史。

业务员范围提示说明未知归属/混合账单未开放；不将过滤后的部分金额标成整单金额，不在不完整范围提供整单确认。页签计数、导出、任务及概览必须复用同一范围，切换身份清掉旧业务视图。


## 0.28门诊移动职责与预约出码

门诊后台账号选项及列表统一“管理员 / 员工”，仅此角色组替换旧机构管理员/业务操作员，资源方和渠道仍为管理员/业务员。移动管理员/员工职责、付款及客户直接出码按[移动设计要求](mini-program-design.md)执行，使用现有Arco体系。没有新增可配置功能权限矩阵。


## 0.29结算、登录与费用状态

原型和正式开发遵守REQ-037：门诊合同区域内办理账期变更并显示旧/新周期、审核状态、原因和日志；沿用Arco Select/Input/Alert和状态Tab，不新建交接模块。期末归集评审工具明确虚构，不混同正式定时任务。金额统一两位小数、四舍五入到分，分配试算明确平台余额；费用锁定时点是核销而非预约。

整单仅机构管理员操作；业务员为本人逐笔明细、小计、同范围页签及Excel，不能把本人小计标成整单金额。后台手机号+验证码，获取/失效/错误有明确反馈，不再显示密码。逾期提示与上下线动作分离，付款后不自动变更人工服务状态。新的移动待恢复状态、特殊撤销提示按移动设计执行。


## 0.29.2预约提醒小窗（项目约定，待原型同步）

遵循REQ-039；本节替代0.29.1的默认大窗交互，不把设计要求标成已实现。门诊登录页以Arco Checkbox显示默认勾选的“登录时开启预约提醒”，它是本机偏好，不是认证授权。登录按钮真实点击时预开紧凑窗，认证中只显示“正在登录”；成功并确定当前门诊后再显示业务。工作台固定保留“开启预约提醒”，旁边显示实际开启状态；失败提供持久Alert且不阻断登录。

紧凑态仅放必要状态文字、数量及“展开”，初始参考320×120 CSS像素；实际遵循浏览器最小尺寸、显示缩放和可读性，不能承诺细条或强制右下角。正文14px、辅助12px、紧凑按钮28px，使用既有Arco变量，不以缩小字体或裁切内容换空间。无待办为中性背景“暂无待处理预约”；有新预约为warning背景/图标加“有 N 条新预约”，另标当前总待确认数。存量只说“有 M 条预约待确认”。不得仅变色或持续闪烁。

点击“展开”调整同一窗口为参考400×520，显示待确认状态Tab、预约编号/意向时间及“去处理”；“去处理”定位原后台独立任务页的具体预约并打开原表单，不新增旁路确认。展开态可沿用0.29.1大数字专项样式；紧凑态不使用56px数字。处理至零保持当前窗口尺寸，用户点击“收起”才回小窗，仍有待办也允许收起；关闭不等于收起，须清楚区分。

展开/收起受浏览器真实用户手势及尺寸约束；请求失败时提示手动调整，保留可读内容和后台入口。加载、断线、权限失效与零待办分别展示；数据过时注明最后更新时间，不用0代替失败。减少动效、键盘焦点、窄窗布局与隐私规则继续适用；浮窗不显示姓名、手机号、来源和财务信息。不添加系统通知、声音或桌面客户端。

## 0.29.1门诊悬浮工作台（历史原型试用）

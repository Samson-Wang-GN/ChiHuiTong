# ADR-0026：手机号授权与客户端凭证隔离

状态：后端实施中，未做真机/真实微信联调。日期：2026-09-12。

## 范围

用户要求小程序暂不动，本轮不修改两个小程序的页面、原型或客户端代码。为全角色后端闭环实现共用的客户权益/预约/反馈接口及门诊授权适配，正式接入仍由后续客户端开发完成。

## 登录与安全决定

- 两个独立AppID分别用于客户端和门诊端。后端向微信交换登录code得到OpenID，再交换手机号code；调用手机号接口时携带刚验证的OpenID，由微信校验两种凭证的绑定关系。不接受请求方提供的手机号/OpenID作为认证依据。
- 校验手机号授权水印AppID和时效，只支持大陆手机号；授权code在本地摘要记录中单次消费，外部调用失败后需重新授权，不保存原始code、session_key或完整微信报文。
- 用户只有手机号即可建立客户登录；未导入且未填写姓名的客户标记资料待完善，预约前补填就诊人姓名。客户登录不覆盖Excel已有姓名；后续导入只可补空姓名，已有姓名不一致仍作为异常。手机号不能自行修改。此项为处理不记名卡新客户的工程默认，供用户审阅。
- 门诊账号必须由后台预先开通且存在有效门诊成员身份，不能因手机号授权自动变成员工；管理员处理合同/账单，员工处理预约。一个手机号同时是客户与门诊员工时，身份在不同应用入口分开，不自动切换工作区。
- Web会话、客户端会话、门诊端会话不能串用。服务端每次检查账号、机构、成员有效状态及请求身份；绑定关系冲突和手机号真实变更不自动迁移。门诊JSAPI支付的OpenID/AppID只从已认证门诊会话读取，不能从付款表单传入。
- 使用普通模式的稳定access_token，短期缓存在服务进程内，不强制刷新使其他服务凭证失效；AppSecret在环境中，access_token不返回前端或写日志。外部HTTPS请求固定域名、禁止重定向、超时8秒、响应限长。

## 限制

AppID、AppSecret、手机号能力、微信商户关联及真实回调环境缺失时明确不可用。模拟测试验证程序行为，不代表主体认证、微信能力开通、真机授权或真实支付验收。审计与权限仍由服务端执行，不依赖小程序隐藏按钮。

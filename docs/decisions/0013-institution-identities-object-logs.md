# ADR-0013 机构身份、业务归属和对象日志

- 日期：2026-09-09
- 状态：已接受（原型；混合账单展示与归属转交待确认）
- 关联：REQ-034、REQ-035、TASK-057～059

## 决定

机构类型与账号身份分离。资源方、渠道账号用管理员/业务员，机构管理员范围为本机构，业务员范围由关联记录决定，不增加菜单按钮权限配置。账号管理仅管理员可操作，是本次明确职责；已有平台审核、收款及渠道不能代核销等边界不被“暂不做功能权限”取消。

平台新增机构在同一次原型保存中登记角色锁定的初始管理员（姓名、手机号、平台创建标记）。机构管理员新增其他身份账号，不能降级初始管理员；账号更新白名单不允许改掉平台创建标记。没有真实密码或邀请短信，也不假装与机构端演示账号同步。生产创建机构/首账号需同一事务及登录账号唯一约束，不能靠手机号文案识别平台创建账号。

渠道关联以门诊负责人账号ID为主；旧演示负责人姓名仅唯一匹配时转为ID，不匹配不开放。资源方已确认以销售订单负责人划分，默认创建人，管理员下单可选择负责人；后续卡/客户权益/预约/核销沿订单关联，不以平台客户唯一归属代替订单范围。同客户其他来源/业务员权益不能一起开放。

## 原型执行边界

共享`management.js`负责身份、投影、保存合并与对象日志。渲染前使用同一范围投影，详情、导出、工作台、任务和概览只接收可见记录；切换账号卸载旧业务视图。原始角色数据单独保留，业务员保存只合并可见记录和本次创建记录，不以投影覆盖其他人的数据。当前会话保留演示身份，页面刷新不会自动变回管理员。

未知归属历史记录不默认分配给任一业务员；混合账单不向业务员暴露整单或整单确认，暂由管理员处理。合作合同/授权产品是机构公共合作资料，保留同机构查看，不开放其他机构。原型未完成历史数据正式补归属、负责人转交及拆分账单设计。

这不是生产认证/租户隔离：本地演示数据可被浏览器读取，身份切换是评审工具，不存在真实服务端权限。生产要求登录主体服务端签发、关联ID鉴权、客户全局匹配的受控边界、不可越权导出及事务/并发审计。不能把前端过滤作为安全实现。

## 门诊运营与日志

平台上下线从详情移到列表按钮和原因弹窗；保留资格/合同/逾期等上线条件，底层兼容`服务中/已暂停`，不改预约履约规则。详情新增独立操作记录Tab。

每次原型业务保存针对门诊、账单、收益结算单及采购订单增加对象ID范围内事件，记录时间、操作人/机构/身份、动作、状态和原因；日志只保存变更字段名，不拷贝敏感载荷。旧处理记录保留并标记历史缺失信息，不能补造事件。正式日志应和业务同事务、幂等且不可篡改；跨机构聚合、系统任务/失败事件和日志保留策略需后端实施。

## 验证

`verify_management.py`覆盖账号锁定/创建、两角色数据投影、混合账单排除、范围合并、刷新身份、新机构首管理员、上线/下线原因及对象日志；回归资料审核、销售、原合同、付款与任务流程。

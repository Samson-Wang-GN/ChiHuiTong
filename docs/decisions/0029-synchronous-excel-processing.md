# ADR-0029 Excel同步识别与校验

- 日期：2026-09-12
- 状态：用户确认，实施中；REQ-046 / TASK-094

## 背景与选择

TASK-093已定位小文件主要等待分钟级队列调度，业务低频且低并发。选择同步请求，不改成常驻worker，也不引入新消息队列。其他开卡、短信、账单等异步流程不变。

## 边界与取舍

`POST /imports`在事务内读取并保存元数据后返回mapping；`POST /imports/{id}/mapping`锁定批次、校验并批量写行后返回validated。严重文件/系统错误回滚本次事务，逐行业务错误正常返回错误清单。已有服务端幂等记录与事务锁保证丢失响应后的相同请求重试不会创建第二个批次/重复校验；不同配置继续用版本拒绝过期提交。同步请求会短时间占用一个Web进程，因此保留文件限制并验证万行耗时，不声称无限并发。

读取器与校验函数保留供旧队列任务完成；新请求不产生excel.inspect/excel.validate任务。旧版本任务仍按批次版本/状态拒绝覆盖新结果；无数据库迁移。回退应用不会破坏已完成批次。

校验先标准化各行，再每500个手机号HMAC索引批量读取客户姓名，比较跨来源的姓名一致性。客户匹配原本就是平台级身份规则，不能错误缩到本机构；只在服务内部使用已有姓名，不对接口或日志返回其他机构客户信息。保留重复手机号、姓名冲突、可选字段、公式及数量验证；此阶段不修改客户。

前端仍是原Arco销售向导，上传自动识别、一次下一步；新请求直接消费结果，不等待worker。仅旧queued批次刷新状态、旧validating在下一步时等待恢复，避免双重轮询。旧GET结果不能覆盖较新版本。静态历史原型和小程序不变。

## 验证与发布

指定服务器临时测试库运行全量后端、无worker的Excel页面专项、2/100/1,000/10,000行三轮同步API性能测试。增加重复/并发幂等、事务回滚、分批查询数量及跨资源冲突测试。发布前备份、记录用户核心数据摘要；更新现有受保护入口，验证四角色及权限/服务状态，保持短信/支付模拟模式。

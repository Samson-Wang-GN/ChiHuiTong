# ADR-0005 周期账单收款与门诊三方合同聚合

- 日期：2026-09-08
- 状态：已接受；逾期、期限及撤销按REQ-037，合同审核及支付阶段按REQ-042；下文旧默认为历史取舍，不再作为待确认项。
- 关联：REQ-006、007、016、018、022、024；TASK-025～029
- 替代：ADR-0003中的渠道双列表及平台—门诊双边合同布局；保留资源方单主合同、多方案和历史版本原则。ADR-0002合同授权及比例/金额分配保留。

## 背景与备选

用户取消门诊授信，改用周/月账单收款并增加微信扫码在线支付；渠道办理门诊合同和优惠需要以门诊为中心。维持授信模型或继续拆分只读页面都会增加无必要操作，与新需求不符。

## 决定

1. 不建设授信额度/调额/待履约风险账本，核销生成获客费，周/月出账。保留付款凭证审核，新增关联账单的微信支付订单；不将其泛化成钱包、充值或三方自动支付分账。
2. 收款使用统一账单/收款边界：线下平台审核实际到账，线上服务端验签/查单核实支付成功。业务订单、付款尝试、收款流水和账单分别记录；重复通知、交叉到账、金额变更及核销撤销须有并发和幂等保护。真实重复款记异常而非删除。
3. 门诊合同改为平台/渠道/门诊三方；渠道组织签订及续签，平台审核。首签/续签、资质及优惠均从门诊管理进入，授权方案仍来自平台—渠道合同，不复制为一套门诊独立费率。
4. 资源方、渠道自身的合同和方案各合为只读页。单合同摘要不强制伪装成列表；嵌入的方案和历史记录列表继续状态Tab。平台配置权不下放。
5. 审核材料按提交版本保存完整清单，全部图片/附件可查看，不仅显示文件名。预览/下载同样执行机构与版本授权，缺失/不可读必需附件阻断通过。

## 代价、安全与未决

取消授信不再封顶门诊应收；逾期已确认只提醒、平台人工上下线，不自动阻断。微信支付本期开发代码和可执行模拟测试，商户主体/开通能力及配置就绪后再真实联调；测试通过、独立高风险评审和启用授权不能由原型演示代替。重复/超额付款完整处置延期，基础防重与流水保留仍必须实现。不得因本ADR存在而自动开通商户、签约或执行真实支付。

三方合同不能由旧双边记录改名得到：保留旧签约主体与附件，真实补签后建立三方版本。当前无生产业务数据，原型样例改造也应保留用户本地历史，迁移不能默默丢弃旧状态。

微信官方[支付通知说明](https://pay.wechatpay.cn/doc/v3/merchant/4012164515)明确验签、金额核验及重复通知处理；官方[回调机制说明](https://pay.wechatpay.cn/doc/v3/partner/4012085875)要求结合查单，2026-09-08核验。上述页面含合单/服务商示例，仅引用通用机制；本项目商户模式与具体产品API未最终选择，不以网页示例作为资质已满足的证据。

## 交付与退出

2026-09-08按用户后续授权已同步四组后台及两个移动原型。新增共享本地工作流展示模块，不新增依赖；以状态Tab列表、门诊详情分区和附件预览落实交互，收款只模拟。旧缓存升级前按角色备份，新增三方样例不代表旧双边合同已补签。授信/双列表测试已调整并新增收款与三方合同专项；验证入口见 `docs/prototype-review.md`。原型代码可退出到旧展示层，旧数据备份不删除；不作为正式数据迁移方案。实际支付上线必须独立开关，可关闭新下单但保留已有订单查单/回调与对账；不能以关闭入口丢弃在途资金结果。正式技术栈未改变。

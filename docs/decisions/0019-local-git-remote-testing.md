# ADR-0019 本地Git与公共服务器文件/测试隔离

- 状态：已接受
- 日期：2026-09-09
- 关联：REQ-040、TASK-070～072

## 背景与决定

用户授权将项目推送至指定GitHub及齿慧开发公共服务器，并要求所有测试只能在公共开发服务器运行。该北京服务器访问GitHub不稳定，用户进一步明确本地才是Git仓库镜像。因此采用普通本地Git工作仓库、本地GitHub通信、SSH传输git archive文件快照；不在服务器保留本项目.git或Github凭据，不使用push --mirror。

目标固定140.143.125.233，主机VM-0-12-ubuntu，目录/home/ubuntu/ChiHuiTong。每提交独立releases目录与SHA-256归档，current软链接指向当前文件版本；测试复制到test-results下，在独立venv顺序执行，只启动临时loopback HTTP。保持共享公共服务/Study System、系统包及现有数据不变。

## 备选方案与取舍

- 服务器git clone/pull：最简单，但违反用户指定边界且受网络影响，排除。
- 直接覆盖单一目录：方便但难追踪和回退，采用提交快照代替。
- 容器或新CI平台：本轮静态原型同步不需要，避免提前决定正式技术栈；未来可单独评审，测试执行地点仍受REQ-040限制。
- 本地浏览器/GitHub托管Runner：即使更快也不符合测试地点要求，排除。

## 后果与验证

本地承担提交和传输，服务器离线于GitHub仍可接收源码；测试产物不污染快照，按提交可复核和回退。代价是需显式传输文件及回填测试证据；依赖安装和浏览器缓存仍需验证。服务器无头Linux测试不能证明Windows原生浮窗行为，这项继续标记未验收，不绕到本机运行测试。

验收：GitHub、本地HEAD和服务器current一致，包摘要一致且无.git，逐脚本测试报告和交付文件哈希不变，既有服务不受影响。正式后端技术栈、数据库、应用入口、CI和生产部署不由本次决定。

# ADR-0006 对账付款、推广产品身份和任务聚合

> 当前口径：付款期限、未结算撤销/已结算禁止撤销已由REQ-037确认；每日管理员对账提醒、0元单无需付款按REQ-042。以下0.19/0.20为历史设计与验证边界，“已入单撤销调整”不适用于当前已结清交易，不能据此恢复旧退款路径。

- 日期：2026-09-08；关联REQ-025～027、TASK-030～033。
- 范围：可交互原型，不开通支付或改变正式技术栈。

## 决定

1. 收益对账与门诊应付账单分开。合作方确认冻结版本，平台上传线下实际付款凭证后进入待确认收款，收款合作方确认到账后已完成；双方均只在职责范围操作。平台不生成自身收款结算单。
2. 明细用独立交易标识和整分金额，导出和界面使用相同授权、状态与关键词范围。原无明细汇总保留历史，不通过均摊金额伪造原交易；另增明确的虚构完整交易样例。
3. 原型通过小型只写模块生成真实OOXML `.xlsx`，只支持平面文本/数值、冻结表头，不引入通用Excel解析库。文本显式inlineStr，不生成公式、宏或外链；ZIP/XML使用标准库独立检验。正式后端选型后以成熟导出库替换，不沿用浏览器权限校验。
4. 产品编号保持稳定，内部名称用于后台、外部名称用于两小程序。原名称只作为兼容别名，不用改名改变授权身份；历史交易名称冻结。
5. 待办从本角色业务状态派生，独立任务页面复用原表单与审核/支付详情，而非复制旁路规则。处理完成记录结果，工作台计数与任务过滤同源。

## 依据与取舍

Excel容器参考Microsoft官方[SpreadsheetML结构](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/structure-of-a-spreadsheetml-document)及[Cell内联字符串](https://learn.microsoft.com/zh-cn/dotnet/api/documentformat.openxml.spreadsheet.cell)，2026-09-08查阅。只实现当前导出所需子集，不支持导入现有Excel或通用电子表格编辑。

无真实跨端同步、服务端机构权限、不可变审计或银行验证。门诊已回款门槛已确认，付款期限和撤销边界已由REQ-037确认，零元单及提醒按REQ-042；历史数据升级前备份，已结账不假冒已付款。退出时保留原型数据备份，关闭新增模块和导出入口；生产迁移/回滚需另行设计。

## 0.20收款闭环补充

每机构/自然月独立结算；一张单保留对账确认、平台付款和合作方收款确认三个事实，最后一步不能由付款方代办。付款后未到账反馈不撤销付款；记录平台核查回复，最终由收款方确认。不新增收款审批单、部分/合并付款或自动转账。旧已付款迁为待确认收款且保留凭证，未补齐依据时阻断确认。原型仍以不同月份的独立虚构样例评审各方操作，不实现跨角色共享或定时出账；正式系统以机构/月唯一键、单据及付款版本、幂等收款事件和事务执行。仅门诊已结清且本合作方尚未入单的历史交易进入当期；按分配记录唯一占用而非按已付款状态防重。保留原核销月、结清日、归集月及历史归属；付款/对账待办采用管理员工作台每日提醒（REQ-042）。部分到账不解锁，未入单撤销不形成正向收益，已入单撤销走独立调整。

# ADR-0028 完整四角色 Web 后台与显式模拟适配器

2026-09-12；REQ-045。状态：已实施并完成本期服务器自动验证，已部署合成验收环境；自主决定待用户审查，真实第三方及生产未验收。

用户要求完成全部后台页面和交互，小程序继续不动。现有轻量接口验收台不能作为完整交付。沿用 React 18.3.1 / Arco React 2.66.16 固定本地发布包及原型的信息架构，不引入另一套设计系统、托管平台或数据库。正式业务视图按领域拆分模块，共享 API、状态列表、业务表单、附件及审计组件；不得发布 localStorage 模拟原型冒充真实系统。

四个独立入口仅装配本角色菜单；业务员与管理员的差异继续由服务端执行。机构与门诊采用列表详情抽屉，合同/推广产品配置置于对象内；合作方本机构合同和产品只读合并展示。删除原验收台的 JSON 调试操作和原始响应详情，以有标签、校验、确认及可恢复错误的业务表单替代。

本期支付与短信实际外发使用显式模拟成功适配器，仅在受保护、独立合成数据库的开发验收模式允许启用。不得在缺少真实商户配置时自动降级模拟。模拟交易、发送记录和页面均标记模拟；真实环境拒绝加载模拟后端。保留已有真实适配器边界和验证代码，但本期不调用真实支付/短信接口。登录仍随机验证码，模拟短信箱不提供通用验证码。

写入使用服务端版本和幂等键；网络不确定时保留同一次操作的键及输入，禁止自动换键重试收款。附件授权下载，不暴露公网原始地址。日志、页面异常和截图不能记录验证码或 Token。

地图与跨 Tab 提醒依赖外部能力，不能以虚构地图或页内浮层冒充实现。地图缺少有效服务配置时明确阻断新定位确认，保留生效坐标与资料；预约提醒使用真实 Document Picture-in-Picture，用户点击登录时预开，失败不阻断登录，工作台可重试。完整功能及验证进度逐项记录在 web-backend-plan.md。

开发测试仅在 140.143.125.233；验收数据持久保留，自动化写入回归使用隔离测试库。所有源码先在本地提交并校验传输，开发服务器不使用 Git。不得改动其他应用服务。生产部署仍须独立评审及真实第三方验收，不能将模拟通过标为真实收款/短信送达通过。
# 地图核对的实现补充

门诊地图使用腾讯静态地图服务经后端定源代理返回 PNG，前端提供真实底图上的点选、缩放、方向移动和显式确认。保留原始底图标识，不在已登录后台载入第三方 JavaScript，不把地图 Key 或业务 Token 交给外部脚本。接口沿用门诊资料权限、租户范围、限流、GCJ-02 地址绑定和平台审核；图片限制为 600×360 PNG、2 MiB，禁止跳转，错误不返回服务商原文。没有地图 Key 或服务失败时禁止确认，绝不以合成图片作为真实定位结果。实际地图服务调用需配置本项目自己的 Key 后复验。

接口参考：[腾讯静态地图官方文档](https://lbs.qq.com/service/staticV2/staticGuide/staticDoc)。当前外部文档访问不稳定；参数及真实底图仍列入凭据就绪后的集成验收，不将传输模拟测试作为地图供应商实测。

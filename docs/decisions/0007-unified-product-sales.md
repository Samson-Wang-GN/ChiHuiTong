# ADR-0007 推广产品销售统一入口

- 状态：已接受（业务与原型边界；生产实现未开始）。
- 日期：2026-09-08；关联REQ-028、TASK-036～038。

采用一张销售订单区分不记名实体卡、记名非实体卡；Excel仅是记名客户录入方式，另支持后台单客户录入。资源方填写采购价，平台收款后审核收费订单，零元订单直接审核。每单一个产品和单价，数量逐客户汇总；提交后不改价。付款确认与审核开卡分开，不把合作方采购款和门诊回款/收益结算混合。

在共享sales.js中复用Arco组件和附件/列表，保留独立角色数据，旧批次和卡订单只读追溯且不自动转成已付款的新单。原型不新增第三方依赖、真实支付或跨端同步。旧缓存先备份，历史卡号不能据旧汇总倒造；新版号段只作独立演示。正式环境用全局唯一卡号、原子高水位和订单幂等键，随机激活凭证独立保存，不使用连续卡号作为领取秘密。

保守默认：同单统一产品/单价/每卡份数，错误明细整单阻断，不部分开卡；改单新建，已付款拒绝/取消保留待退款；取消卡号不复用。零元订单也必须平台审核。小程序单客购买仍延期，本轮只开放资源方后台录入。

页面合并不合并付款、审核、权益领取、卡片与客户身份等业务事实。真实匹配/并发、Excel安全、号段迁移、细化权限和跨端联调需正式实施；原型通过不允许直接上线。
备选方案：保留Excel/购卡两个入口会重复维护采购付款及审核；直接把旧汇总转换为已付款新单会虚构事实。选择统一订单与只读历史区，以明确迁移边界为代价降低新业务重复实现。原始缓存升级前备份，回退原型脚本时也须恢复对应旧缓存，不能把新订单静默丢弃。新模块不改变部署或正式技术栈，后续替换演示解析器/本地序列时须通过同一业务验收。

# ADR-0023 微信支付可信观察与入账

状态：实施中；真实主体、商户号和回调域名尚未配置，不执行真实收款。关联TASK-079/085、REQ-043。

## 决定

- 先实现普通商户APIv3：后台Native、门诊小程序后端JSAPI；不修改小程序UI，不接入微信分账或自动退款。若未来申请服务商主体，需单独调整适配，不假定参数通用。
- 商户签名私钥和APIv3密钥仅在运行环境；微信公钥采用固定可信ID映射，支持同时保留新旧公钥。未知ID、过期时间戳、错误签名、重复JSON键及解密失败拒绝。
- HTTPS固定官方域名，禁止重定向和环境代理转发签名头；签名覆盖原始报文，响应验签后使用。外部I/O不持有账单事务锁。
- 付款订单先落库并绑定账单版本、金额、商户与AppID，再向微信下单。15分钟支付期限，不将本地到期误当成微信已关单；未决支付阻止线下凭证和账单交易撤销。
- 回调验签解密及身份/金额校验后持久化最小金融数据和发件箱，快速应答；异步入账与主动查单共用幂等资金流水，成功不能被迟到的未支付结果覆盖。
- 无效/重复回调不能重复结清。真实多收或过期版本来款保存异常流水，不冒充正常冲销；未决资金仅供平台核查，不实现用户暂缓的完整超额款退款流程。
- JSAPI付款身份来自后端核实的门诊小程序登录绑定，不能接受客户端自由填写OpenID。未配置时明确提示使用付款凭证，禁止自动转模拟支付。

## 测试与限制

测试仅在指定开发服务器，以运行时生成的RSA/AES测试密钥、合成报文、模拟网关覆盖签名/解密/重放、下单未决、回调与查单竞态、完整付款及越权。最终仍须配置主体后验证商户绑定、真实签名、公网HTTPS回调及真实小额支付；这些不以模拟测试替代。

# ADR-0022 正式后端与独立数据库测试

- 日期：2026-09-12；状态：采纳，实施中。
- 关联：REQ-043、TASK-081～088；替代早期“后端尚未选型”的目标描述，不改写旧原型验收事实。

## 决定

采用 Python 3.12、Django 5.2 LTS、Django REST framework、PostgreSQL 16 的模块化单体。服务端业务服务执行权限、状态机及事务，接口层负责输入校验与投影；不开放可以任意改状态的通用模型CRUD。API统一 `/api/v1/`，四个后台保留独立角色上下文，同一个手机号的不同机构身份必须显式选择并再次鉴权。

选择理由：服务器已有Python3.12及PG16二进制；Django提供成熟迁移、事务、校验和测试体系。不为本期引入微服务、容器平台、Redis或Celery。后台任务采用PostgreSQL持久任务/事务发件箱，管理命令领取、重试及定时处理；业务提交不依赖短信成功，实际压测后再决定是否拆队列。

2026-09-12核对：[Django官方下载页](https://www.djangoproject.com/download/)列明5.2.17及LTS支持至2028年4月；[DRF官方发布说明](https://www.django-rest-framework.org/community/release-notes/)和[PyPI元数据](https://pypi.org/project/djangorestframework/)为兼容与版本依据。依赖精确锁定，升级需服务器回归；保留上游许可证。退出可通过标准SQL及数据导出，不依赖托管数据库私有能力。

## 隔离与安全

- 服务器仍为140.143.125.233，项目根 `/home/ubuntu/ChiHuiTong`。独立 `.venv-backend`，不修改原型环境。
- 用现有PG16二进制在本项目 `runtime/postgres` 初始化独立实例，只监听本项目0700 Unix socket目录，端口标识55432。不连接/修改共享5432实例，不开放TCP或公网端口。
- 本地提交归档，服务器无Git；测试在独立副本运行，日志注明提交和主机。数据库、附件、密钥、日志均在源码快照之外。
- 敏感字段和导入原始资料应用层加密；规范化手机号用独立密钥HMAC索引；随机凭证只保存摘要或受控加密值。缺少密钥启动失败，不生成默认生产密钥。
- 金额整分/Decimal四舍五入；关键写操作采用约束、行锁、幂等和不可变历史；前端不能指定机构身份、可信金额或支付成功。
- 不开放通用Django admin。平台首个账号由显式管理命令开通，不提交默认密码/验证码。短信和支付缺配置时明确不可用，不返回假成功。

## 范围与取舍

小程序暂不动解释为不修改客户端页面或微信工程；仍实现销售、领取、预约、核销共享领域服务与接口，才能完整验证四后台。真实外部能力分别记录适配代码、模拟契约、真实联调，不将模拟算真实接入。

未决细节集中记录于[后端实施清单](../backend-plan.md)，供用户审阅。交接、发票、复杂争议裁决及其他报表继续延期。数据库任务降低运维复杂度，代价是须处理租约、重试及监控；规模增加时可在明确边界换队列，不改业务事务。

## 验证

独立PG实例执行迁移、框架检查、API/领域/并发测试、lint、覆盖率和启动冒烟；不用SQLite代替行锁。全部使用合成数据；共享服务前后检查且不改配置。逐阶段保留失败和复测证据，不以基础CRUD或文件数量代替业务完成。

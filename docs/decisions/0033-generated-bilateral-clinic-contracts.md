# ADR-0033 双方门诊合同生成及签署前草稿

日期：2026-09-16。状态：业务流程确认，待正式合同范本后实施。关联REQ-051 / TASK-110；覆盖ADR-0032中单列旧合同类别的界面决定，不追溯改写已有财务及签署证据。

## 决定

门诊合同只有平台与门诊签约主体两方，渠道仅代办。平台—资源方、平台—渠道仍分别管理，三方收益分配不受影响。不再把旧模型或旧阶段口径暴露成独立合同分类。

先保存可恢复的资料/合同草稿，完整填写合同必要项后按平台认可范本生成供下载打印的文件，再上传门诊签署件并提交；不再以“已有签署附件”为保存/生成前提。单店继续联合审核，连锁仍总部合同与逐店资料分步审核。

倾向固定模板生成PDF而非允许业务员自由编辑条款；具体渲染依赖待读取正式范本后选择，优先现有栈和可验证的中文分页方案，不为此引入电子签平台或通用合同编辑器。缺模板时不填充自创的法律条款，不把测试样张发布为真实合同。

模板版本、填写字段、门店覆盖、产品及计费条款组成不可变生成快照。签署件绑定该快照，正文修改后旧件不满足新版本提交，但仍保留审计；模板升级不修改已签文件。生成/下载必须服务端鉴权，重复生成同一版本不能重复创建主体、编号或产生不一致文件。

## 兼容与实施约束

取消业务概念不授权删除保存的附件/账单、重写签字原件或改变既有款项归属。先清理当前需求及界面/API分类，旧数据和模型适配由实现任务明确处理；涉及数据转换先备份并在指定开发服务器测试。历史提交、迁移和测试事实保留为工程记录，但不再作为现行产品规则。

验收需覆盖真实模板打印视觉、字段齐全、版本一致性、受权访问、单店联合审核、连锁分步审核及兼容记录；模板未提供前本决定不代表已完成开发、文件生成或发布。

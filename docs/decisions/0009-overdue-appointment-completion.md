# ADR-0009 预约自动完成与真实核销分离

- 状态：已接受（需求与原型设计）
- 日期：2026-09-09
- 关联：REQ-030、TASK-042～044

## 背景及选择

预约时间过去并不能证明患者爽约或治疗完成。按用户确认保留四个预约主状态，72小时自动设为完成；以独立完成来源/说明区分系统关闭和真实核销，不新增“已到店”主状态。取消2小时提醒，24小时门诊待办，门诊报患者未到取消但保留权益，客户本人申请才自动释放。

不采用超时自动释放或按系统完成直接收费；这两种方式分别可能导致重复使用权益和无依据收费。也不为此增加未授权的完整争议仲裁流程。客户与门诊冲突仅记录并停止自动处理。

## 决定与后果

预约主状态、完成来源、实际核销、权益占用、反馈和待办轮次分别保存。72小时关闭原待办，客户确认已到诊后生成新的待补核销任务，保留原任务历史。恢复权益与实际核销互斥；所有费用及分配仅从有效核销产生，不从“完成”推断。

原型复用固定Arco组件及无依赖的共享规则模块，不新增后端或跨角色同步。保留各组独立记录，演示时钟明确标注；无依据的旧待办只读。代价是不能用原型证明微信、定时任务或数据库事务正确性。正式服务端需权限、预约版本锁、幂等事件、可审计恢复/核销记录和通知重试。

权益已过期后能否补核销仍待业务确认；当前拒绝过期核销，恢复只解除占用、不延长有效期。REQ-029按主状态计算的预约数可能包含系统完成，但核销指标仅按真实核销事件；页面必须解释区别。

## 验证

运行`python -X utf8 prototypes/verify_overdue.py`及已有原型回归，检查24/72小时边界、改期重计时、未到/已到冲突、先恢复后扫码/先扫码后恢复、重复操作、原数量/费用、角色入口与移动布局。跨角色反馈的自动化验证只进行显式测试夹具传递，不宣称生产联动。

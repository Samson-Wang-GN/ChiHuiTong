# 正式小程序代码与接入交接

2026-09-13；REQ-047 / TASK-097～100 / ADR-0030。这里是正式微信原生代码，不是`prototypes/*-mini`浏览器演示。真实账号未提供，本轮只交付代码、服务器构建及能够完成的测试，不标记微信发布完成。

## 工程与业务范围

`mini-programs/src/customer/`为客户端，`src/clinic/`为门诊端；`routes.json`维护14个客户页面与25个门诊页面。`native/`是原生WXML/WXSS卡片、表单和二维码组件模板，`src/shared/`是请求、会话、控制器和展示类型。构建时产生两个完全独立的微信工程，分别注册App/Page/Component，不混合角色，不依赖WebView或浏览器原型数据。

- 客户：手机号授权、首页待领取/待处理提示、规则卡片直接预约、实体卡扫码激活、手动或定位查门诊、已审核坐标地图和图片、意向预约、直接展示核销二维码、取消/改期、过期预约反馈与待恢复权益、消息和可选个人资料。
- 门诊：手机号授权及多门诊身份选择、独立待办、预约确认/拒绝/改期审核/协商改期、过期预约处理、扫码核对/报价/确认治疗/核销/撤销、消息；管理员专属合同/授权产品、账单/逐笔交易/Excel、付款凭证、微信付款/继续付款/查单/关闭及操作记录。
- 移动视觉继承Arco品牌色与状态语义，使用原生控件和移动设计尺寸；后台官方React/Arco组件不进入小程序包。未进行微信真机视觉验收，不能用旧浏览器截图代替。

## 配置就绪后的接入步骤

1. 客户、门诊各自申请独立AppID，确认主体、服务类目、手机号能力、隐私保护指引和相关接口资格。不要在聊天中发送AppSecret或私钥。
2. 后端私有环境分别填写已有`CHT_MINI_CUSTOMER_APPID/SECRET`、`CHT_MINI_CLINIC_APPID/SECRET`；更新本次后端代码并验证。支付商户配置另行完成，缺配置时不假装真实成功。
3. 从`mini-programs/config.example.json`生成部署私有配置，仅填写公开的`appid`、`apiBase`、`privacyReady`。两个AppID不得相同；正式隐私指引完成前保持false。编译用`CHT_MINI_BUILD_CONFIG`指向该JSON；`CHT_SOURCE_COMMIT`由运行器注入。
4. `apiBase`为批准的HTTPS API根地址（不含`/api/v1`）；配置微信request/downloadFile/uploadFile合法域名。当前受Basic保护的后台入口**不能直接作为小程序接入方案**，不得把其访问口令写进包；独立小程序API入口的网关授权、限流与WeChat登录仍需账号就绪后落实，不能简单关闭现有保护。
5. 在允许的验证环境导入各自构建目录，绑定相应AppID，执行原生编译、开发者/体验版和真机验收。目前仍遵守全部测试仅服务器；若需本地微信开发者工具或手机，先取得用户针对该项的明确例外授权。
6. 分别上传、审核与发布。现阶段不调用微信上传、不改变线上Nginx、不开放新端口、不向现有验收库增加真实客户或模拟小程序身份。

## 必须后补的真实验收

- 两端真实微信登录/手机号/隐私同意与拒绝、未开通/停用员工、同号码不同AppID、多门诊切换。
- 微信原生编译、375/390/430px页面及安全区域、返回/切后台/重进、长规则和空列表。
- 真机相机识别卡码与预约码、GCJ-02定位拒绝/成功、地图点位与联系电话、图片与PDF/Excel附件。
- 同机JSAPI真实付款、取消/超时/断网/后台通知/重复查单，服务端一致到账与账单版本变化；真实商户、主体和回调未具备前不能标为通过。
- 同号双端完整履约、24/72小时任务、客服/门诊反馈冲突提示、特殊补核销撤销后的待恢复。

## 重要自主决定与修复

- 会话只存在内存，重启需重新授权；不缓存客户档案或QR到持久存储。页面隐藏清空敏感展示，身份变化清空旧缓存，服务端仍最终鉴权。临时附件在退出/切换身份时清理；不在打开微信附件预览导致的App隐藏瞬间删除正在查看的文件。
- 保留共同展示模板但各自业务模块和路由独立；客户包不含门诊财务业务模块。采用编译期共享，无运行时跨应用角色切换。
- 预约时间统一北京时间显示；有效期按最后确认预约日比较，不按晚到的扫码日拒绝合法补核销。
- 修复客户改期接口的既有JSON序列化缺陷：待改期的UUID/时间明确转字符串，避免幂等结果存储触发500。二维码在冻结、冲突、待改期、待恢复及无合法预约日时不返回。
- 付款重进页面读取原支付单；结果未知先查单，不能直接再创建。模拟标记始终显示“未产生真实资金”，不会调用真实微信支付。上传付款凭证为真实文件业务接口，未审核不结清。
- 扩展门诊小程序只读支付记录与Excel导出路由，复用服务端管理员/机构边界；不允许借支付记录路由提交后台扫码支付请求。
- 本轮不修改合同、结算周期、分配算法和门诊上下线业务规则；不引入数据迁移。现有Web验收应用保持既有发布，源码同步不等于已部署小程序API更新。

# ADR-0004 两个独立移动交互原型

- 日期：2026-09-07；状态：原型工程方案已采用；关联REQ-023、TASK-024。

客户和门诊为两个独立小程序，沿用已有React/Arco固定本地依赖实现可直接打开的移动网页原型，不引入新构建工具或新生产技术栈。手机布局复用Arco主题及输入控件，不压缩Web后台表格；移动尺寸、底部导航及卡片为项目级设计约定。

两端独立脚本和存储，公共目录仅提供UI助手。不构建演示后端，也不为跨端联动在客户端下发门诊员工/其他客户数据。代价是两端无法联动，核销和预约使用各端独立场景；优点是角色边界可审查，明确区别可交互原型与真实服务。

真实微信授权、定位、相机、短信、会计处理及定时任务均保留为正式接入工作。固定凭证为不可核销视觉示意，使用明确标注的演示编号模拟扫码结果；不得投放真实卡或将原型作为医疗履约系统。微信官方网页本次读取失败，正式开发前重新核验API及平台设计要求。

0.23补充：在独立存储不变的前提下，共享`prototypes/shared/overdue.js`的纯规则及展示组件，避免客户恢复与门诊补核销规则漂移；不是共享角色业务记录或建立跨端同步。参见[ADR-0009](0009-overdue-appointment-completion.md)。

## 建议验收顺序

1. 平台：机构管理进入详情，分别检查机构资料、合作合同、多产品配置、来源展示名和账号；来源方及渠道机构的产品配置只在平台管理。一个合同支持多个产品，比例/金额实时试算；超额分配拒绝并保留输入。
2. 渠道：门诊管理进入同样的详情抽屉，检查资料、完整附件、三方合同及产品上下线。修改已审核资料后，由平台在变更审核中对照原值和申请值；退回不覆盖原版。合同退回可登记新版本，续签带入主合同编号。
3. 资源方：推广产品销售三步向导，分别尝试实体数量、记名单客和Excel批量。Excel上传即自动读取/匹配，直接看原表列头和前10行；必填的姓名、手机号、开卡数量未匹配时标红并选原列。核对后只点底部“下一步”，自动全表校验并进入产品采购步骤；可选字段和工作表/表头设置可展开，缺数量可明确填写统一张数。错误留在原步骤，删除/更换文件立即使旧结果失效。已提交订单的“Excel导入依据”可保存本机构格式供下次自动匹配。非零采购价仍必须先核实收款再审核开卡。
4. 门诊：预约详情确认日期时间、协商改期、无法接诊、过期预约及扫码核销。核销必须使用完整固定权益码，并核对服务和费用；尚未到预约时间不能核销。已结清交易不可撤销。系统完成后的补核销撤销保持待申请恢复，不直接释放权益。
5. 门诊账单：检查逐笔交易、状态筛选、Excel、凭证和日志；上传付款凭证由平台审核。部分收款只记账，全部收到才结清。模拟微信支付按钮会明确提示没有真实资金往来，然后通过账本完成模拟结清。
6. 合作方结算单：各自管理员确认对账，平台登记线下付款和附件，各自确认收款；0元单无需付款。业务员只能查看本人明细，不可处理机构整单。未收到门诊全额款项的交易不会归入合作方单。
7. 平台及资源方：客户与权益概览点击每个指标，查看日/周/月曲线、精确数值和明细，按当前范围下载Excel。系统自动完成不等于核销，也不产生获客费。
8. 工作台：各待办卡片进入对应类型的待处理页面；站内消息可打开相关对象，合同到期提醒可进入续签。读消息不会完成业务。平台可处理账单异议、配置短信模板/工作日日历并查看失败任务及重试。
9. 账号：机构初始管理员角色锁定；机构管理员可新建管理员/业务员。门诊员工不显示合同、账单和账号管理。业务员按负责关系看到数据，无数据时正常显示空列表，不扩大权限。
10. 门诊提醒：支持的桌面浏览器在点击登录后尝试开启真实Document PiP紧凑窗；新预约更新数量，点击展开进入处理，处理后收起。关闭后不会自行重开，使用工作台“开启预约提醒”恢复。不支持或被策略阻止时显示原因，后台和模拟通知流程仍可使用。

## 验收边界

- 所有页面操作写入服务器数据库，刷新后以服务器为准。附件经鉴权和安全检查，图片/PDF可预览并保留下载替代。
- 自动回归在指定服务器随机独立测试库运行，不清空本入口的持久演示数据。自动化覆盖范围见实施清单，不代表穷尽所有人工浏览器组合。
- 本期按用户要求不调用真实微信支付或短信接口；真实商户/签名报备/回调/到账送达仍须独立验收。
- 地图代码包含真实底图代理、点击选点和确认，但缺少本项目地图Key时无法完成真实地图联调；不能以示意图替代，不允许把未加载地图的选点确认为准确定位。门诊其他业务规则仍按已确认合同及审核规则执行。
- 不新增小程序界面；不实现业务员交接、发票、复杂支付退款争议等已明确延期事项。生产发布仍需独立安全评审和真实外部服务验收。

# ADR-0033 双方门诊合同生成及签署前草稿

日期：2026-09-16。状态：已实施并部署开发验收；正式法律范本由平台配置并验收后启用实际签署。关联REQ-051 / TASK-110；覆盖ADR-0032中单列旧合同类别的界面决定，不追溯改写已有财务及签署证据。

后续实施决定：平台在受权后台发布固定纯文本正文，使用白名单`{{字段}}`替换；不执行HTML、脚本或模板表达式，不提供任意模板引擎。ReportLab 5.0.1（[官方元数据](https://pypi.org/pypi/reportlab/json)）生成PDF，复用服务器已有文泉驿中文TrueType字体并嵌入子集，pypdf继续检查文件安全，Poppler作视觉验收。依赖只限后端生成器，可替换渲染函数退出；不在持久验收环境预置自创合同。PDF技能的容器标记脚本及Node不在本项目服务器，无法调用；沿用项目强制服务器验证，样张仅合成测试产物，不交付为实际合同。

## 决定

门诊合同只有平台与门诊签约主体两方，渠道仅代办。平台—资源方、平台—渠道仍分别管理，三方收益分配不受影响。不再把旧模型或旧阶段口径暴露成独立合同分类。

先保存可恢复的资料/合同草稿，完整填写合同必要项后按平台认可范本生成供下载打印的文件，再上传门诊签署件并提交；不再以“已有签署附件”为保存/生成前提。单店继续联合审核，连锁仍总部合同与逐店资料分步审核。

采用固定纯文本模板生成PDF，不允许业务员自由编辑条款，不引入电子签平台或通用合同编辑器。平台发布模板须显式确认正文已获认可；每次发布生成新版本，替换当前适用模板而不覆盖旧版本。PDF固定添加填写信息摘要，避免模板遗漏变量造成打印内容与系统数据不一致；所有字段做文本转义。缺模板时不填充自创的法律条款，不把测试样张发布为真实合同。

模板版本、填写字段、门店覆盖、产品及计费条款组成不可变生成快照。签署件绑定该快照，正文修改后旧件不满足新版本提交，但仍保留审计；模板升级不修改已签文件。生成/下载必须服务端鉴权，重复生成同一版本不能重复创建主体、编号或产生不一致文件。

## 兼容与实施约束

取消业务概念不授权删除保存的附件/账单、重写签字原件或改变既有款项归属。先清理当前需求及界面/API分类，旧数据和模型适配由实现任务明确处理；涉及数据转换先备份并在指定开发服务器测试。历史提交、迁移和测试事实保留为工程记录，但不再作为现行产品规则。

验收分两层：合成模板验证代码、中文分页、字段齐全、版本一致性、受权访问、单店联合审核、连锁先签约和续签；正式模板到位后仍需核对实际条款、完整正文及签字/盖章位置，不以合成样张代替法律文本验收。连锁合同无门店时允许先完成总部审核，但门店上线仍检查签署覆盖；退回补正复用主体/门店而重新生成对应版本，不批量迁移旧数据。
